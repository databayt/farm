# Website implementation plan

Status: Stage 6 draft · Date: 2026-10-19 · Companion to `sitemap.md` and `website-copy.md`
Stack (already in this repo [V package.json, 2026-10-19]): Next.js 16.4.2 (App Router), React 19.3, Tailwind CSS 4, shadcn (style radix-nova, Radix and Base UI primitives, lucide icons), Fumadocs 16 for the `/docs` study site, zod 4, TypeScript, pnpm. `AGENTS.md` requires reading `node_modules/next/dist/docs/` before writing code; where this plan names a Next.js 16 convention it comes from those docs [V GTM-06].

## 0. Principles

1. **Go live only with real progress to show** (§13). Until then the site exists in the repo and on a private preview.
2. **Do not rewrite what exists.** `/docs` (the study) stays as it is. The public site is new routes in the same app, sharing `components/ui` and `globals.css`.
3. **No speculative product as available.** The data model enforces it (§4).
4. **Cheap to run and to change** by a non-developer founder: content in files, no database at launch.
5. **Privacy by design:** collect little, keep briefly, no ad trackers.

## 1. Architecture

```
src/app/
  (site)/                # public routes, own layout (header, footer, status banner)
    page.tsx             # Home
    about/ model/ produce/ livestock/ sustainability/ technology/
    quality/ business/ partners/ journal/ progress/ contact/ privacy/ terms/ sources/
    lots/[code]/         # L1
  docs/                  # existing study site (unchanged)
  api/enquiry/route.ts   # form endpoint (or a server action)
  sitemap.ts  robots.ts  opengraph-image.tsx  not-found.tsx
content/
  docs/                  # generated by scripts/sync-docs.mjs (do not edit)
  journal/*.mdx          # posts: frontmatter + body
  site/status.json       # product-line states, validated by zod
  site/progress.json     # gate table
  site/site.json         # name, contact, confirmed facts (empty until confirmed)
src/lib/site/            # schemas (zod), content loaders, claims guard
```

- **Rendering:** static (SSG) for every public page; only `/api/enquiry` is dynamic. This keeps hosting cost and attack surface low.
- **Content:** MDX via the Fumadocs/MDX toolchain already in the repo for the journal; JSON for the status board and progress table. All JSON passes through a zod schema at build time; a build fails if a product's state is "available" without a delivery date and a spec link.
- **`/docs` exposure:** the study contains buyer contact details copied from public sources, outreach drafts, internal assessments and financial runs. **It must not be served publicly by accident.** Before any deploy: put `/docs` behind access control (Cloudflare Access, or exclude it from the public build), set `noindex` on it, and decide page by page what becomes public (`/sources` extracts). `scripts/sync-docs.mjs` lists the pages shown in `/docs`; the new files in `go-to-market/`, `brand/`, `investment/` and `website/` are not yet in its list and **should be added only to the private docs**, not to the public site.
- **Proxy:** Next.js 16 names middleware `proxy.ts` [V GTM-06]. Use it only for locale routing if languages are added (§9) and for security headers if not set in hosting.

## 2. Design system

- **Base:** the repo's shadcn `radix-nova` setup (`components.json`, `src/components/ui`). Add only the components needed: button, input, textarea, select, label, checkbox, card, badge, table, alert, tabs (optional), separator, sheet (mobile nav).
- **Tokens** (Tailwind 4 CSS variables in `globals.css`): colours from `../brand/brand.md` §10 (Leaf, Lake, Clay, Ripe, Chalk, Soil dark) mapped to `--primary`, `--accent`, `--background`, `--foreground`, `--warning`, with a dark scheme. All text pairs checked to WCAG AA contrast (4.5:1 for body, 3:1 for large text and UI).
- **Type:** the repo loads Geist and Geist Mono; keep them (full Latin with diacritics for Kinyarwanda). Mono for lot codes and numbers. Body 16-18 px, line-height 1.6, measure 60-75 characters.
- **Components specific to the farm:**
  - `StatusChip` (Planned, Planted, In harvest, Available, Paused) with icon and text, never colour alone.
  - `EvidenceTag` (V, E, A, U) with a tooltip and link to `/sources`.
  - `ProductRow`, `GateTable`, `JournalCard`, `PhotoPlaceholder` ("Photo to come: [subject]"), `Figure` (requires caption, date, photographer).
  - `EnquiryForm` (typed by audience).
- **Photographs:** `next/image`, real photos only; a `Figure` without `alt` and `caption` fails type checking. Strip GPS metadata before commit if the location is private.
- **Dark mode and print:** dark scheme via `prefers-color-scheme`; a print stylesheet for spec sheets.

## 4. The "no speculative products" guard

- `status.json` schema: `{ id, name, state, stateDate, summary, specUrl?, availableFrom?, deliveryRef? }`.
- Rules enforced in code and tests:
  1. If `state = "available"` then `deliveryRef` (a real delivery note ID) and `stateDate` are required.
  2. No price or order button is rendered unless `state` is `available` or `in-harvest`, and prices are "on request" at launch.
  3. Copy lint (a build-time check): fails the build on the words "organic", "certified", "pesticide-free", "export-ready", "100%", "guaranteed", "award", "trusted by", "our customers", "our partners" unless the page has an explicit allow-list entry with an evidence reference in `claims.json`.
  4. `site.json` location fields empty until the founder confirms; pages hide the location sentence when empty.

## 5. SEO

- Metadata API per page (title ≤ 60, description ≤ 155), canonical URLs, Open Graph and Twitter cards, a generated OG image (text-only until real photos exist).
- `app/sitemap.ts` and `app/robots.ts` (Next.js file conventions [V GTM-06]); sitemap lists public pages only; `/docs`, preview hosts and `/api` are disallowed and `noindex`.
- Structured data: `Organization` (name, URL, contact) once the legal name is known. **No `Product` or `Offer` schema** and no `LocalBusiness` address until the location is confirmed and the founder agrees to publish it.
- Content plan for search: the journal posts (honest, specific, dated) and `/sources`; target terms are long-tail and in English first ("farm-gate avocado prices Rwanda e-Soko", "outgrower avocado Rwanda"); no keyword stuffing. Expect little search traffic early; the real discovery route is direct outreach with the site as proof [A].
- Search Console and the sitemap submitted after launch.

## 6. Accessibility

- Target WCAG 2.2 AA [A: the standard the site is held to].
- Semantic HTML, one `h1` per page, landmarks, skip link, visible focus, keyboard-operable nav and forms, labels bound to inputs, error messages tied to fields (`aria-describedby`), `aria-live` for form results.
- Colour is never the only signal; touch targets 44 px; respects reduced-motion; no autoplay media; alt text for every informative image; tables with headers/captions.
- Checks: axe in Playwright on every public route in light and dark; manual keyboard and screen-reader pass (VoiceOver, NVDA) before launch; 200% zoom and 320 px width without horizontal scroll.

## 7. Performance

Budgets [A, to be tested on a mid-range Android phone over throttled 4G; no Rwandan network data was collected]:
LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.1, total JS ≤ 150 kB gzip per page, page weight ≤ 500 kB before images, images ≤ 120 kB each at the largest displayed size.
Measures: static generation; Server Components by default; minimal client JS (the form and tooltips only); `next/image` with explicit sizes and AVIF/WebP; self-hosted fonts via `next/font`; no third-party scripts at launch; cache headers on assets; Lighthouse CI in the testing plan with failing thresholds; check bundle with the Next.js analyzer.

## 8. Contact form, spam protection, privacy, analytics

### 8.1 Form
- Three audiences (buyer, partner/supplier, investor/adviser) plus community and other, chosen first; fields per `website-copy.md`.
- Validation with zod on client and server; strict length limits; reject HTML in fields; normalise phone numbers (Rwanda +250).
- Endpoint: `POST /api/enquiry`. On success: send an email to the founder and an acknowledgement to the sender; append a row to a private log for the buyer register. Keep the log in the founder's own mailbox or sheet at first (no database), unless the lawyer confirms hosting data elsewhere is acceptable (see 8.3).
- Accessibility: all errors announced; no CAPTCHA that blocks screen-reader users.

### 8.2 Spam protection (layered, cheapest first)
1. Honeypot field hidden from users and assistive tech.
2. Time trap: reject submissions faster than 3 seconds after load.
3. Rate limit per IP and per email (e.g. 5 per hour) at the hosting edge.
4. A privacy-friendly challenge (Cloudflare Turnstile is the natural fit on the founder's lane; verify its current terms and data handling before use [U]).
5. Server-side checks: origin and content-type, payload size, URL count in the message (reject more than two links).
6. Email deliverability: SPF, DKIM and DMARC on the sending domain; send from the domain, not a free address.
7. Log rejected counts, not message contents.

### 8.3 Privacy and Rwandan data law
- Rwanda's personal data law (No 058/2021) is reported to require controller/processor registration with the supervisory authority (NCSA), to apply to organisations processing the data of people in Rwanda even without a local presence, and to restrict storage abroad and transfers (reported Arts 48 and 50) [C GTM-01, GTM-02; read from secondary summaries, gazette text not opened]. **A Rwandan lawyer must confirm** whether the farm must register, whether form data may be stored on foreign infrastructure and what the breach duty is, **before the form goes live** [U].
- Until then: minimum fields, no analytics identifiers, no storage on third-party platforms beyond transient email transport, a short retention period (24 months), a deletion route by email, and a privacy notice written in plain language (draft in `website-copy.md`).
- Consent checkbox on every form; no pre-ticked boxes; no newsletter without a separate opt-in.
- No cookie banner needed if no non-essential cookies are set; keep it that way.

### 8.4 Analytics
- Privacy-first, cookieless measurement: page views, referrers, countries, form submissions by type, core web vitals. Options on the Cloudflare lane: Cloudflare Web Analytics (cookieless; confirm current behaviour [U]) or a self-hosted/EU privacy-first tool. No Google Analytics, no advertising pixels.
- UTM parameters on outreach links (`?utm_source=email&utm_campaign=buyer-interview`) to see which messages bring visits; stored only in aggregate.
- Weekly look; a monthly line in the progress notes. Analytics inform the website, not the farm's market decisions.

## 9. Languages (en / rw / fr) — evaluation on evidence

| Evidence | Finding |
|---|---|
| Kinyarwanda | Spoken by over 99.7% of Rwandans; 54% of residents aged 15+ are literate in Kinyarwanda only [E GTM-03 via UNESCO summary of the 2022 census] |
| English | Literate in Kinyarwanda and English: 14.1% (21.6% in Kigali) [E GTM-03] |
| French | Literate in French: 1.9% of residents aged 15+, down from 3.1% in 2012 [E GTM-03] |
| Official languages | Kinyarwanda, English, French, Kiswahili [E GTM-03] |
| Our audiences | Buyers: hotels, grocers, exporters (English likely used in business; Kinyarwanda in daily dealings) [A]; partners and investors: English; neighbours and workers: Kinyarwanda [A] |
| Our capacity | One founder; a translation needs a native speaker and upkeep; stale translations are worse than none |

**Decision [A]:**
- **L0: English only**, plain and short, written to be easy to translate.
- **L1: Kinyarwanda for the pages that serve Rwandans directly:** Home, Business, Contact, Privacy, Progress summary. Translated or reviewed by a native speaker. Triggered when interviews show buyers or staff prefer it, or when the first neighbours/workers ask.
- **French: not justified by the evidence** (1.9% literacy) unless a buyer or partner asks for it in interviews.
- **Technical:** design routes so languages can be added without rewrites: `app/[lang]/(site)/...` with a dictionary file per locale and a `proxy.ts` that negotiates locale per the Next.js 16 i18n guide [V GTM-06]. At L0, `lang="en"` and no prefix; add prefixes at L1. `hreflang` tags when more than one language exists. Right-to-left support is not needed.
- Never auto-translate and publish without a native review.

## 10. Hosting and deployment (Cloudflare lane)

- The founder's usual lane is Cloudflare. For Next.js on Workers there are two routes: the OpenNext adapter for Cloudflare (`@opennextjs/cloudflare`, `wrangler.jsonc`, `nodejs_compat`) and Cloudflare's own framework guide [C GTM-04, GTM-05 from search summaries]. The Next.js 16 docs list Cloudflare as still working on a verified adapter and offering its own integration [V GTM-06]. A search summary also suggests Cloudflare now recommends a different tool for new Next.js apps; this is unverified [U]. **Before choosing, run the `cloudflare` skill and re-read the live Cloudflare and OpenNext pages, and test with Next 16.4.2.**
- **Fallback with the lowest risk:** because every public page is static, build with static export for the public site and deploy it as static assets, with a small Worker for `/api/enquiry`. This avoids adapter risk entirely. (Static export disables some Next features; the `/docs` search route may need to stay out of the public build.)
- **Environments:** local (`pnpm dev`, port 3000 per the founder's rule), private preview (Cloudflare preview URL behind Access), production. Secrets (email API key, Turnstile secret) in Cloudflare, never in the repo; one central `.env` locally per the founder's rule.
- **Domain:** not chosen (the farm has no name). Buy after the name decision; DNS on Cloudflare; HTTPS enforced; HSTS after testing.
- **Security headers:** CSP (self only at launch), `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, frame-ancestors none.
- **Cost [U]:** domain (annual), email-sending service (free tier), Workers/Pages plan (a free or low-cost tier may suffice for a static site; confirm current pricing), analytics (free). Expected total is small; get the quotes at deployment time and record them in the model's overheads (they are real overhead).
- **Deployment steps:** (1) pass the test plan locally; (2) `pnpm build`; (3) deploy to preview with the chosen adapter; (4) run the checks in §11 on the preview; (5) deploy to production through the founder's `deploy` skill; (6) verify the live site: screenshots, console, network, form test; (7) record the release in the decision log. Rollback: redeploy the previous version from Cloudflare's deployment list.
- **Commit workflow:** main-only, small conventional commits (project rule).

## 13. Launch criteria: "real progress to show"

Go live only when **all** hold:
1. G0 passed (location and title known) and the founder has decided what location detail to publish.
2. At least six real photographs taken by the team, with captions and dates.
3. At least two journal posts with real content (for example the site visit and the first buyer interviews).
4. The Progress page has at least G0 and G1 entries with evidence.
5. Lawyer sign-off on privacy and the form.
6. A name, a domain and a sending email address.
7. All P0 tasks done and the testing plan green.

If the farm is not ready, keep the site private; a "coming soon" page is not needed. Until launch, use the study docs (private) and the executive summary for introductions.

## 14. Maintenance

- Weekly (15 minutes): update status JSON and progress table if anything changed; publish a journal post when something real happened.
- Monthly: dependency updates (`pnpm update`, audit), Lighthouse run, link check, review of analytics and complaints.
- Quarterly: content review against the evidence labels; remove stale claims; review languages in light of interview findings.
- Ownership: the founder owns the accounts (domain, Cloudflare, email); credentials in a password manager; a second person with recovery access.
